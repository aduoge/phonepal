# 选火车票并准备订单

按用户明确的阶段执行。只查票时停在车次结果，不创建订单或候补订单。使用铁路12306（com.MobileTicket）；没有安装时说明需要安装，不能假装已查询。

1. 从任务与当前日期确认出发地、目的地、乘车日期、人数、出发/到达时间要求、席别和预算。相对日期必须换成具体日期；不明确时集中 ask_user。城市可包含多个车站，“上海”和“上海虹桥”不能擅自等同。
2. 打开12306，检查实际可选日期；未开售或超出页面可售日期时说明，不虚构余票。登录或验证码由用户接管。查询不需要乘客证件时，不提前索取证件号。
3. 设置出发地、目的地、具体日期；根据要求筛选高铁/动车、出发时段、到达时段或席别。查询后再核对页面条件，避免把默认日期当成用户日期。
4. 从当前结果中选最多三班有意义的候选，报告车次、出发/到达站、时间、历时、指定席别票价和该席别余票状态。其他席别“有票”不代表用户席别有票。候补、无票、未开售要按页面原意说明，不报“保证能买到”。
5. 推荐理由对应用户条件：早到、价格低、换乘少或车站合适。没有满足全部要求的车次，先说明冲突，让用户选是否调整。只要求比较时在这里 finish，并标注“查票完成，尚未预订”。
6. 用户明确选择车次并要求准备订单后，进入预订页；核对既有乘车人，未经明确指定不能默认勾选第一个人。姓名、证件和手机号在手机上确认，不复制进共享材料。
7. 提交前展示具体日期、车次、起止站、出发/到达时间、席别、人数、总金额和页面可见的退改信息。看不到某项就说未确认。候补、加速包、保险和收费附加服务需要单独明确选择，不自动开启。
8. 对本笔明确的订单摘要 ask_user，收到确认并通过 Sentinel 后才提交。付款由用户在手机完成。用户完成后再读订单状态，区分“已提交/待支付”和“已支付/已出票”；没有订单证据不能宣称买票成功，也不要重复提交。

finish 说明完成到哪一步、结果依据和下一步。一次只处理一个阶段，用户选车次后再发起下一阶段；避免在一次长操作里自行决定行程、乘客和支付。
