# 按需求点一餐外卖

按任务当前阶段执行。只要求查询或比较时，到候选结果就结束，不往购物车加菜。要求准备订单时做到订单确认页；准备订单不等于获准提交。

1. 先读目标和已有偏好，明确人数、预算、菜品或口味、送达要求。会影响筛选的缺项集中 ask_user 一次；用户当次要求优先于记忆。过敏原缺少店铺说明时明确无法确认，不作安全保证。
2. 启动已安装的美团主 App（com.sankuai.meituan），进入“外卖”；若仅安装美团外卖独立版，则使用 com.sankuai.meituan.takeoutnew。需要登录、验证码或授权接管时 ask_user，不能把跳过登录当作已登录。
3. 查询阶段可使用当前展示的配送区域，但不擅自切换或新建地址。按关键词和条件找最多两家候选，除非用户要求更多。只引用屏幕可见的店铺、菜品、价格、配送费和预计送达时间。优惠有门槛时一起说明；未到结算页的“到手价”不能充当已核实总价。
   点击商品卡后检查画面是否真的进入详情。若节点点击返回成功但画面未变，下一次改为按当前截图点击图片或标题的坐标，不反复点击同一节点；替代点击仍无效时说明无法进入详情，返回已核实的候选与未知项。不要点击加号、拼单或购买按钮来代替只读查看详情。
4. 返回两种方案和推荐理由，请用户选店或授权选择。若目标只是查询，在此 finish，说明“候选已找到”，不能说“已下单”。预算内没有合适结果时说明差额或缺失条件，由用户决定是否放宽。
5. 用户选定后，核对已有购物车；有原有商品时先问，不覆盖、不清空。进入所选店铺，只加入本次明确选定的菜品、规格、数量，核对主食是否包含、辣度和备注。售罄或规格不符时问用户，不能自行换成更贵的菜品。
6. 进入订单确认页，核对实际配送地址与当次要求；向用户展示店铺、菜品规格和份数、餐费、包装费、配送费、已生效优惠、最终应付和预计送达。手机号和地址只在手机上核对，不抄进公共分享材料。预估送达不是准时保证。
7. 所有金额以当前结算页为准。超过预算、出现会员/自动续费/附加服务，或价格与选定方案变化时先处理并重新确认。停在提交前，ask_user 提供本笔订单摘要。先前的“选这家”不等于确认提交订单。
8. 用户明确确认本笔订单后，才可提交，仍需通过 Sentinel 的确认。支付页面由用户亲自完成。不得输入支付密码、代点免密支付或把“允许一次”扩大到之后的订单。
9. 用户完成支付并让你继续后，重新读取订单页面。看到订单编号和对应状态才报告已创建/已支付；没有结果则说明待核实，不重复提交。

finish 的 summary 写实际阶段（候选已找到 / 订单待确认 / 已下单待支付 / 页面显示已支付）、关键结果和下一步。课堂演练若要求停在候选或订单确认页，严格在该阶段结束。
