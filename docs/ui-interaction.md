# 小满聊天与任务界面

本轮参考 Open Muse 的信息层级，在 Android Compose 中独立实现。参考源码为 `chyroc/open-muse` 提交 `051a2f0`，没有搬用其头像或前端代码。

| 参考位置 | 可借鉴的交互 | 小满的实现 |
|---|---|---|
| `src/ChatUI.tsx` 的 ChatHeader | 名称旁显示简短状态 | 小满标题、就绪/处理中/等你确认 |
| `src/chat.css` | 留白、轻量气泡、清楚的主次 | 稳定绿色主题，浅色和深色模式；跟随系统字体缩放 |
| `src/styles.css` 的 activity-toggle | 过程按需展开 | 连续进度记录收进“处理过程”，问题、错误和回答保持可见 |
| `src/message-cards.css` | 结果与普通过程分开呈现 | 助手结果用独立卡片，支持基础粗体和列表 |

确认卡片固定在聊天底部，自动收起键盘；优先展示“暂不允许”和“允许一次”，“同类操作都允许”放在更多选项。批准后仍须回到目标 App，并重新核对页面；没有取消原有确认规则。

悬浮任务条只在小满页面之外显示，点击文字可返回任务；停止按钮继续保留，执行手势和截图时仍临时隐藏悬浮条。

首页“选一本笔记本”只填写一句可编辑的中文，需要用户点击发送才执行。购物默认规则由助手承担：普通规格、数量1、含运费预算、核对结算后停止。它们是模型指引，支付前仍依赖独立确认机制，不能把提示词当成硬性权限控制。

真机验收应覆盖：大字体布局、中文发送、过程展开、确认按钮、返回目标 App、停止、真实结果。Open Muse 是 Web/Capacitor UI，小满是原生 Compose；本轮借鉴交互结构，保留小满的应用架构。

## 本轮实测（2026年11月2日）

在 vivo V2141A / Android 14 上安装本轮 debug APK，保留系统字体缩放 1.25001 和显示密度 704。直接点击首页中文示例，再点击发送：

> 帮我在淘宝挑一本20元以内的A5笔记本，选好后给我确认。

任务 `app-20261102-225742-pc64` 成功执行10个手机动作，经过2次“允许一次”，进入确认订单页。页面和回复均为【牛皮】A5·1本、每本72页、数量1、2.40元包邮；没有提交订单或支付，也没有遇到验证码。该账号已有上一轮淘宝路径记忆，价格包含当次平台优惠，不代表全新账号的通用价格或所有购物场景均已验证。

真机已检查首页、中文发送、过程展开和收起、底部确认卡片、批准后返回淘宝、结果卡片、小满前台不显示任务悬浮条。深色模式和其他机型未做本轮真机验收。

`test :app:assembleDebug` 通过，共226次JUnit测试执行，0失败、0错误（包含debug/release，非226个独立场景）。“10万+人付款”导致的多余确认仍存在，不能当成已修复；此处保留为进阶开发题。
